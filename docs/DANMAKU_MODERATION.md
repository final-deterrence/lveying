# 弹幕限流与自动审核

后台入口：**弹幕管理 → 限流与自动审核**（`/admin/danmaku/settings`）。配置保存在 SQLite，保存后立即用于新请求，不需要重启，不需要额外数据库或审核服务。配置和试审接口仅允许管理员访问。

## 观众与后台的行为

观众端保留“弹幕经审核后将公开展示”，有效提交后统一显示“发送成功”，不显示限流规则、倒计时或审核结论。服务器返回相同的 `{ "success": true }`，不提供可探测的审核状态或消息 ID。格式错误、超长内容、网络故障和服务器故障仍会提示失败。

“发送成功”表示提交已处理，不保证进入展示：

| 服务端处理 | 后台结果 | 是否公开 |
| --- | --- | --- |
| 命中限流、重复或已封禁 IP | 按天累计拦截次数，不为每次请求保存弹幕 | 否 |
| 命中内容禁用词 | 保存到“已拦截”，保留内容与原因供复核 | 否 |
| 完整匹配允许短句 | 保存为“已通过”，标记自动审核及命中短句 | 是 |
| 无法由规则明确判断 | 保存到“待审核” | 人工通过后公开 |

管理员可以将记录通过、拦截或转回待审，纠正误判；通过后仍能撤回。修改词表只影响新提交，不会追溯批量放行旧弹幕。封禁 IP 会撤回该 IP 已公开的弹幕，将相关记录标为拦截；解封不自动恢复。

## 默认规则与修改方法

服务端使用滚动的 60 秒窗口：

- 同一浏览器发送间隔至少 5 秒，每分钟最多 10 条。
- 同一 IP 每分钟最多 300 条；IPv6 按 /64 网段汇总。
- 同一浏览器一分钟内重复内容过滤（统一全半角、大小写和连续空白）；其他观众发送相同口号不受此项影响。
- 请求体实际读取上限为 4 KiB，即使没有或伪造 `Content-Length` 也适用。

校园网可能很多人共用出口 IP。300 条只是初始值，应彩排确认并在后台调整；浏览器配额、IP 配额、去重及自动审核均可配置。浏览器使用匿名 Cookie 标记，清理或伪造 Cookie 可以绕过浏览器配额，但仍受 IP 配额限制，因此不是账号级身份校验。

限频检查、计数、弹幕写入和审核结果在同一 SQLite 事务内，多个进程同时提交不能超卖配额。重启应用、删除或清空弹幕不会重置一分钟配额。过期限频记录定期清理；限流、重复、封禁请求只做按日聚合，保留约 30 天，后台可刷新查看今日统计（北京时间）。同一请求命中多项限制时只计一项，内容规则拦截另外统计在弹幕列表中。

首次默认允许“加油、太棒了、好听、好看、学生节快乐、演出顺利、辛苦了”等整句。匹配时统一全半角和大小写，可忽略末尾常见语气标点，例如“加油！”；不会因为一句话包含“加油”就放行。隐藏字符和附加文字不会被白名单自动忽略。

禁用词初始提供两条明显辱骂词作示例，组织者应根据活动需求修改。禁用词优先于白名单，包含即拦截，并统一全半角、大小写，忽略空白、标点和常见隐藏格式字符。这有助于识别简单拆字刷屏，但仍可能误伤引用，也无法覆盖谐音、复杂语境等变体。不要把词表当作完整内容安全审核。

两份词表各最多 200 条，每行 1–40 字，不支持正则表达式。可先用“试审”测试当前编辑中的规则；试审不发送弹幕，也不会保存规则。关闭自动审核后，新弹幕均转人工，限流和 IP 封禁仍按自己的开关工作。

默认阈值也可通过环境变量指定；尚未在后台保存配置时生效。后台保存后以数据库为准：

```dotenv
DANMAKU_SEND_INTERVAL_SECONDS=5
DANMAKU_CLIENT_PER_MINUTE=10
DANMAKU_IP_PER_MINUTE=300
```

## 生产环境真实 IP

应用仅接受入口覆盖的 `X-Real-IP`，不使用客户端可以伪造的 `X-Forwarded-For` 链。生产环境没有有效 `X-Real-IP` 时，弹幕 POST 返回 503，并且不会入队；本地 `npm run dev` 缺少头部时使用回环地址。

**必须同时满足下列两项**：

1. 应用只绑定宿主机 `127.0.0.1`；Docker 用 `127.0.0.1:28880:8880` 发布端口，容器内监听 `0.0.0.0:8880`。不要在公网开放应用端口。
2. 现有 Nginx 的本站子域名反向代理覆盖头部，而不是透传观众提供的值：

```nginx
# 在本站的 server/location 中，使用现有证书配置。
location / {
    proxy_pass http://127.0.0.1:28880;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

只信任头部本身不能证明来源，禁止直接公网访问应用端口是必要条件。如果入口前还有腾讯云 CLB、CDN 或其他代理，应先为 Nginx 配置只信任这些代理地址的 realip 规则，再使用恢复后的 `$remote_addr`；不要对全网信任来访头部，否则会被伪造，或者所有观众被当成同一个代理 IP。

## 对抗大量无效请求

应用限流主要减少刷屏与审核积压，大量无效 HTTP 请求仍会消耗应用资源。可在 Nginx 为本站弹幕 POST 增加请求频率限制，提前挡住请求；不要限制所有 GET，否则会影响观众轮询。

以下为可选示例，额度同样需要考虑校园网共享出口。只给本站的弹幕接口引用该区域，不给 `eesast.com` 原站添加限制：

```nginx
# http {} 内（通常可放入被 http 引入的独立 conf.d 文件）
map $request_method $lveying_danmaku_post_ip {
    default "";
    POST $binary_remote_addr;
}
limit_req_zone $lveying_danmaku_post_ip zone=lveying_danmaku_post:10m rate=10r/s;

# 本站 HTTPS server {} 内，其他 location 保留
location = /api/danmaku {
    limit_req zone=lveying_danmaku_post burst=50 nodelay;
    limit_req_status 429;
    client_max_body_size 4k;
    proxy_pass http://127.0.0.1:28880;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

入口 Nginx 返回的 429 在观众页面同样显示发送成功，但不会计入应用后台统计，应查本站的 Nginx 日志。更大规模的分布式流量需要结合腾讯云入口防护；这套代码不等于 DDoS 防护。

## 更进一步的审核辅助

当前选择本地规则，避免在活动当天依赖外部审核请求。若需要识别广告、辱骂的更多变体，可以以后接入腾讯云文本内容安全：明确违规结果拦截，其余可疑或超时、失败结果转人工。白名单依然保持整句、保守匹配。大模型可以辅助标注，但不建议仅凭模型输出直接把未知内容送上大屏；当前没有接入或发送数据给任何外部审核服务。
